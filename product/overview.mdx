This inventory is based on source inspection, not a production acceptance test. Implemented means concrete code was found; placeholder means the route currently renders an unavailable view. Deployment availability remains to confirm. [S01]

## Modules

| Module | Audience and purpose | Evidence status |
| --- | --- | --- |
| [Files and library](/product/files) | Counsel uploads, finds, and reviews documents | Implemented; capabilities depend on access |
| [Knowledge and memory](/product/knowledge) | Counsel knowledge, memory, gaps, and quality | Placeholder; implementation to confirm |
| [Client intake and verification](/product/intake) | Clients describe a matter, check facts, and submit identity materials | Intake v2 implemented; legacy v1 coexists |
| [Engagement, quotes, and payment](/product/engagements) | Counsel decides acceptance; clients review quotes and pay | Implemented; payment-provider availability to confirm |
| [Client workspace](/product/client) | Clients track matters, messages, files, and deliveries | Implemented; visibility rules apply |
| [Counsel document work](/product/counsel) | Counsel manages a matter, reviews documents, and delivers work | Implemented; separate quality/knowledge/memory/gaps pages are placeholders |
| [Settings and access](/product/settings) | Workspace users locate account and organization controls | Routes implemented; full role matrix and commercial entitlements to confirm |

## Planned and unavailable scope

The UI specification describes counsel knowledge review states, scoped memory, prioritized gaps, and a quality board. Their dedicated routes currently render placeholders. Treat these as specified intentions pending implementation confirmation, without an inferred release date. The delivery checklist also reserves a format-check row but explicitly says no format checker exists yet. [S02, S12]
