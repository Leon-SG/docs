The client workspace at `/orbid/client` brings together matter progress, communication, files, requested actions, engagement payments, and received deliveries. It follows intake handoff and uses organization and matter visibility checks. [S17]

## Work on a matter

1. Sign in with the client organization account associated with the matter or invitation.
2. Open the relevant matter and inspect the current status and outstanding actions.
3. Respond to information or document requests and review files before confirming them.
4. Choose the intended recipient where offered. The choice controls whether the assistant is asked to respond; it does not make the message a private conversation hidden from counsel. [S33]
5. Review a current quote and complete the available payment action when required.
6. Open delivered files, inspect the accompanying information, and acknowledge receipt when that action is available.

The inspected v2 progress bar derives its stage from the current engagement status and delivery flag; it is not a complete event log. In particular, a paid status maps to the work stage without proving that a background task started. Open the available details and confirm uncertain milestones with the firm. [S36]

A pending delivery acknowledgment, payable quote, or outstanding client action can take precedence in the status summary. An outstanding client action is checked before completion; otherwise, a completed matter remains completed even if older responsibility metadata remains. A waiting or processing indicator is not an assurance that counsel has accepted, completed, or delivered the work.

## Visibility and access

The company association and relevant workspace must match the client session for the inspected paid-matter read rule. An additional matter/member visibility layer may apply: in the inspected code it is enforced only when enabled; shadow mode records differences without blocking, and off mode does not consult it. Confirm the deployment setting before relying on this restriction. [S25] A bound client account records who linked the matter; it does not by itself describe the full membership permission model.

A colleague's invitation or shared token does not automatically grant access. If denied, check the signed-in email, company, invitation recipient, and matter association with the firm. Never infer universal company-member access from one helper function alone. [Q13](/product/open-questions)

## Files, failures, and status

In the inspected drafting v2 path, a client sees delivered task files only after lawyer approval and delivery. A delivery can list multiple files, which can be downloaded individually. The download route checks the recorded file integrity and can refuse a missing or mismatched file; if a download fails, confirm the matter and delivery status and contact the firm rather than assuming the file was received. [S42]

For the inspected NDA task delivery, the formal document may be accompanied by a client-language translation or, for a revision, a tracked-changes copy against the client’s base document. These links appear only when the corresponding files are available and bound to the delivered formal output. The product labels the translation as a non-binding reference and says the formal text prevails; ask counsel about the documents’ legal effect. If an expected copy is missing, contact the firm. [S41]

Distinguish files requested from you, files you supplied, and files delivered by counsel. Confirm that you are viewing the right matter and document version before responding or acknowledging. If an upload, payment, or message fails, inspect its saved or returned state before retrying.

For the inspected KYC supplement flow, open the requested checklist item and provide the requested file through the available upload control. Check the item status after uploading; a file being provided does not itself mean counsel has verified it. Earlier requests may also contain separately listed document items. If a request is withdrawn or an upload fails, refresh its status and contact the firm before retrying. [S28]

For separately listed legacy document-request items, the inspected upload control uses the chat-attachment rules: `.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.csv`, or `.txt`, up to **50 MiB per file**. These are different from the [KYC identity-material limits](/product/intake) and do not describe every upload path. [S37]

In the inspected legacy receipt flow, acknowledgment requires a name and creates or reuses an invoice record. When newly created, the invoice amount is calculated in USD from intake module pricing, not from the current engagement quote. Compare the invoice with the agreed quote and actual payment; contact the firm if they differ. The NDA task delivery path does not create an invoice from the task record; availability depends on the applicable delivery record. [S24] See [Q16](/product/open-questions) for the unresolved reconciliation question.

Status logic includes waiting for assignment, work by the assistant or lawyer, client action, delivery, and completion. Time estimates depend on regional and deployment configuration; this manual provides no guaranteed response time. Delivery acknowledgment is receipt handling, not a substitute for reviewing the professional content.

See [intake](/product/intake), [engagements](/product/engagements), and [shared rules](/product/rules). Notification channels, membership roles, and service-time commitments remain [Q13](/product/open-questions).
