Files support matter analysis, drafting, and review. The counsel library is a firm workspace; matter-specific client files have separate visibility rules. [S11]

## Counsel library

The implemented counsel library at `/orbid/counsel/library` provides document lists, search, upload, status filters, and document details. Its view options include documents, search, standards, templates, and a management view that depends on returned capabilities. The presence of the templates view does not establish every template-authoring operation. [S11]

1. Open the counsel library and search or filter for the relevant document.
2. Open its detail view to inspect the file and associated information.
3. Upload new material when the operation is available to your account.
4. Use management operations only when your returned capabilities permit them.

In the inspected library permission model, firm-visible documents are available to eligible readers in that firm workspace. A restricted firm document is limited to its uploader, named users, and actors with the relevant administrative capability. The inspected helper treats documents in the official shared workspace as readable by eligible library readers, subject to the applicable route; an account with client-only roles has no library capability. Check the document’s visibility and your account permissions if a colleague cannot find it. This does not establish the complete deployed role matrix. [S39]

In the inspected original-download path, seeing a firm document is not enough to download its original: the requester must be its uploader or have the relevant firm administration capability, and the original must still be available. The original is not the desensitized copy. If access is denied or the file is unavailable, ask the uploader or firm administrator; handle the original according to your organization’s policies. [S52]

Where the matter-file interface offers archive to library, an authorized user can copy an eligible delivered file into the firm library. The inspected path excludes drafts, redlines and client uploads, checks the file, and leaves the matter file in place. Identical content can return an existing library record; a new record still needs processing and may require review. The bulk action submits at most **20** files at a time; inspect results and check for files still unarchived. [S30, S55]

Client matter files and lawyer deliverables also appear in the [client workspace](/product/client); that is a matter-specific flow rather than evidence of access to the entire firm library.

## Search results

In the inspected search interface, enter search text or select a clause type to enable search; a contract type or language filter alone is not sufficient. [S31]

The inspected clause search combines keyword and semantic results when available, with optional reranking. If semantic search is unconfigured or unavailable, it can return keyword-only results; if reranking fails, results remain in the earlier order. The inspected interface shows a notice for semantic unavailability, but does not show every degradation reason. The inspected interface requests the default limit of **20** results, scoped to what the reader may access. Try relevant terms and filters, check source and permitted use, and do not treat an empty result or ranking as proof that no relevant material exists. [S31]

## Limits and failures

The inspected counsel library upload dialog accepts `.docx`, `.doc`, `.pdf`, `.txt`, and `.md` files up to **50 MiB each**; it skips empty files, hidden filenames, and Office temporary filenames beginning with `~$`. The server checks the uploaded bytes before registration. Identical content already in the firm library can be returned as a duplicate, and registration does not itself mean extraction has finished. These rules are specific to the library upload dialog. [S21]

The upload dialog offers a choice to retain the original and defaults to retaining it for a newly registered document. If retention is turned off, the inspected processing code attempts to remove the stored original after extracted clauses are saved; removal can fail. An existing duplicate may be returned instead of registering a new document, so do not assume the current selection changes that existing record. Confirm the original’s availability before relying on download or reprocessing. [S21, S30]

After upload, inspect the document status. The inspected library pipeline uses `queued`, `parsing`, `desensitizing`, `classifying`, `needs_review`, `ready`, and `failed`. A document in `needs_review` requires review; an authorized reviewer may complete it only after the applicable checks pass. The inspected library clause search and drafting-source path uses clauses from `ready` documents, so upload or registration alone does not make those clauses available there. [S30]

For `queued`, `needs_review`, or `failed` documents, the detail view may offer a re-run when the original is retained and the account has upload capability. Check the resulting status; a re-run request does not by itself establish that processing succeeded. [S30]

In the inspected review flow, completion can be allowed when the named-entity recognition service is unconfigured or the language is unsupported. A `ready` status therefore does not prove that named-entity recognition ran or that all sensitive information was removed. Review the material and the reported scan state before relying on it. [S35]

In the inspected firm-document deletion path, an authorized library administrator can remove a document and its clauses and embeddings; templates keep their text but lose the deleted source reference. Deletion is refused for licensed documents and while the document is being processed. Storage removal is attempted afterward and can fail, so a successful record deletion does not prove the original was removed from storage. Check the reported result and follow your firm’s retention process. [S53]

The inspected library management path allows an authorized administrator to configure retention from upload or last use and preview affected documents. In this implementation, last use means a document’s clause was used as a drafting source; merely viewing it is not shown to reset that date. Recording this use is best effort and can fail without stopping drafting, so recent use does not guarantee the date was updated. A setting that would make documents immediately due requires confirmation of the previewed count, and the scheduled job can delete eligible expired documents. No setting means this retention rule is off, not a general preservation guarantee. Confirm the deployed setting, job availability, and firm policy before relying on retention. [S54]

A failed upload, extraction, or preview does not prove that the file is empty or unsupported in all circumstances. Check the reported failure and retry the affected operation. Confirm file identity before relying on source quotations. Other upload paths, extraction behavior, deletion rights, retention, and indexing delays remain [Q04](/product/open-questions).
