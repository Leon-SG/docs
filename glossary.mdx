# Glossary

This page defines Orbid AI bid-ops terms (scan, match, fill, cellmap, residual, formal match, go/no-go). It is for documentation consistency—not marketing metrics. Broader regulatory encyclopedias live on [orbid.dev/glossary](https://orbid.dev/glossary).

- **Scan** — Structure tender files into requirements and form signals
- **Match** — Compare product specs to requirements (`run_match`)
- **Fill** — Write responses into buyer forms (`run_fill_excel`)
- **Deliver** — Produce exportable artifacts/packages
- **Cellmap** — Map of form cells to requirement semantics
- **Residual** — Empty/uncertain cell after automation
- **Quick rank** — Shortlist of candidate products
- **Formal match** — Parameter-level comparison after product lock
- **Product lock** — Commit to one model for formal work
- **Deviation** — Documented non-conformance vs requirement
- **Compliance matrix** — Requirement×response status table
- **Go/No-Go** — Bid/no-bid decision support
- **Hard limit** — Mandatory pass/fail requirement
- **Bidder response** — Values the bidder enters (vs source data columns)
- **Orbid AI** — Product name (formerly MedStrato)
